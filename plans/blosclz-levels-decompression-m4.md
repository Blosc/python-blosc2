# Gradual BloscLZ hash sizes and ARM64 decoding

## Decision

Keep the gradual schedule:

```c
{0, 8, 9, 10, 11, 12, 13, 14, 14, 14}
```

It speeds up levels 2–6 on both requested ramps, with **identical compressed
sizes** in every cell. Keep the independently tested ARM64 decoder improvements
too: they help floating-point reads, but do not materially improve integer-ramp
reads.

This follows [the first level-1 experiment](blosclz-synthetic-tuning-m4.md).
Raw measurements and source/extension hashes are in
[`blosclz-levels-decompression-m4.json`](blosclz-levels-decompression-m4.json).

## Hash schedule: levels 2–6

One billion elements, 12 threads, `clevel=2..6`,
`SHUFFLE + BYTEDELTA`, default `int64` arange / `float64` linspace,
`chunks=(2_000_000,)`, `blocks=(16_000,)`. Medians of five measured trials
after one warmup, rotating constructor/codec/level order. Each cell includes
an LZ4 control at the same compression level.

The following comparison changes **only the schedule**, retaining the original
decoder in both packages:

| Level | Hash bits before → after | `arange` before → after | `linspace` before → after |
| ---: | ---: | ---: | ---: |
| 2 | 13 → 9 | 102.13 → **91.65 ms** | 195.77 → **162.38 ms** |
| 3 | 14 → 10 | 113.10 → **92.96 ms** | 216.66 → **166.68 ms** |
| 4 | 14 → 11 | 114.67 → **96.26 ms** | 228.07 → **177.92 ms** |
| 5 | 14 → 12 | 114.30 → **98.55 ms** | 227.26 → **193.53 ms** |
| 6 | 14 → 13 | 114.55 → **102.81 ms** | 227.62 → **206.50 ms** |

Savings are 10–18% for `arange` and 9–23% for `linspace`.
At every level, both schedules produced:

- `arange`: **21,714,257 bytes**, 368.42x.
- `linspace`: **275,530,493 bytes**, 29.03x.

Level 1 retains the previous 8-bit table and `3/3` match tuning. Levels 2–6
retain their `4/4` match tuning; levels 7–9 retain their 14-bit tables. This
experiment does not extend level-1 short-match tuning to other levels.

The schedule saves table clearing and, at some levels, entropy-probe work.
The probe limit is `min(length-derived sample, 1 << hashlog)`. For a
16,000-byte split, level 6 already samples 8,000 bytes with either schedule;
its improvement is not attributable to a shorter probe.

**Scope:** this supports the gradual policy for synthetic ramps, not a claim
that the smaller tables always retain ratio on real-world data. They can
increase collisions or change probe rejection on other inputs. A heterogeneous
corpus remains appropriate before making a general ratio guarantee.

## Decoder review and changes

The format and encoded payload are unchanged. Changes in
`../c-blosc2/blosc/blosclz.c`:

1. On ARM64, copy matches in **16-byte groups** when both distance and output
   slack permit it; retain the 8-byte path for smaller distances. Each individual
   copy is non-overlapping, while ordered iterations preserve LZ overlap
   propagation.
2. Inline **16-/32-byte literal copies** when input and output have enough
   space. Only logically consumed literal bytes advance the pointers.
   Exact-size/tail cases retain the bounded copy.
3. Consume **eight consecutive 255-byte length extensions** together, checking
   input availability and accumulated-length limits before advancing.
4. Express match-copy slack checks with subtraction rather than `len + slack`,
   avoiding signed addition overflow in the check.

The new fast paths are ARM64-only; other architectures retain their existing
decoder paths apart from the overflow-safe slack check. A NEON broadcast path
for short power-of-two match distances was tested and rejected: it slowed the
floating-point cases.

### Raw codec measurements

Direct decoder calls, not including filters or framing, on identical payloads
generated by the original encoder. Four offsets into each synthetic dataset,
16,000 elements per block, each shuffled/differenced byte plane, compression
levels 1 and 5. One warmup plus five rotating-order batches of 500 decoder
calls. Aggregation excludes constant planes, which Blosc can encode specially
without invoking the codec.

| Dataset | Raw decoder time reduction |
| --- | ---: |
| Integer ramp | 10.6% |
| Floating-point ramp | 17.3% |
| Sine wave | 17.7% |

These are warm-cache microbenchmarks, not predicted end-to-end read gains.
The large integer-ramp microbenchmark improvement does not translate into a
significant full-pipeline improvement.

### Matched read measurements

Three sessions in alternating package order, comparing **smooth schedule with
old decoder** against **the same schedule with the new decoder**. For each
array, read 100 spread-out chunks (1.6 GB logical bytes), alternating allocated
slices and reused-destination `schunk.decompress_chunk` calls. One warmup plus
five measured sweeps per session; tables report pooled medians.

Canonical hashes of compressed blocks in logical order match between packages
and sessions. Physical block ordering can vary with compression threads, so
hashing whole chunks without canonicalization is not a valid equality check.
The first session verifies **every element** of every billion-element array
in both packages, outside the timing.

| Dataset / level | Reused destination: old → new | Reduction |
| --- | ---: | ---: |
| `arange`, 1 | 22.456 → 22.406 ms | 0.2% |
| `arange`, 2 | 22.523 → 22.366 ms | 0.7% |
| `arange`, 5 | 22.553 → 22.345 ms | 0.9% |
| `linspace`, 1 | 28.043 → **26.803 ms** | **4.4%** |
| `linspace`, 2 | 29.707 → **28.020 ms** | **5.7%** |
| `linspace`, 5 | 29.641 → **27.982 ms** | **5.6%** |

Allocating `linspace` slices improve 1.6–2.2%; `arange` slice differences are
below 0.5%. Treat the integer-ramp changes as effectively unchanged, not a
meaningful speedup. LZ4 controls remain approximately unchanged. Inverse filters,
output writes and Python allocation mask much of the raw codec improvement.

## Validation

- **1,735 native CTest cases passed**, 76.03 s.
- **331 Python ndarray tests passed** against the isolated final package.
- The expanded native regression passes **ASan+UBSan** with the codec,
  fast-copy code and test instrumented. Alignment checking is disabled for
  pre-existing unaligned scalar casts; linked dependencies are not fully
  sanitizer-instrumented.
- Decoder streams built independently of the encoder cover match distances
  1–64, lengths 3–65,536, literal/overlap boundaries, unaligned input/output,
  exact-size buffers, undersized output and truncated input.
- **14,420 valid/mutated/truncated/random decoder cases** give identical return
  values and successful decoded contents with the original and new decoders.
  2,567 cases return successful decodes; malformed cases are not counted as
  valid roundtrips.
- Full billion-element validation and compressed-block hash comparisons in the
  read experiment cover BloscLZ levels 1, 2, 5 and the level-1 LZ4 control.
- After publishing native commit `a68fa2aad2bd51714da7f8974c8def5ad1f391ff`,
  a fresh wheel build fetched that exact pin without a native source override.
  The extracted wheel passed all 331 ndarray tests and full-value checks of
  1,000,003-element BloscLZ ramps at levels 1–6. The shared installation was
  not replaced.

supports multiple levels, reused-destination reads and full validation:

```sh
conda run -n blosc2 python -S scripts/benchmark_blosclz_constructors.py \
  --package /path/to/isolated-package --output levels.json \
  --levels 2 3 4 5 6 --repeats 5 --warmups 1 \
  --read-chunks 100 --read-mode chunk --validate-all
```

Use `--read-mode slice` for allocating reads. Measurements of the final package
with both changes are also retained in the JSON; constructor times remain close
to the isolated schedule measurements above.
